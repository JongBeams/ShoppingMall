# 쇼핑몰 상담 RAG 에이전트 (LangGraph + Ollama tool calling)

규칙 기반 추천 챗(`/chat/smart`)은 키워드·로그인 여부로 if-else 분기했습니다. 정해진 경로만 탈 수 있었고,
평가에서 상품명 환각(개인화 10회 중 3회), 프롬프트 잘림(4,096 토큰 창 초과), 한국어 답변 속 중국어 혼입이 나왔습니다.
에이전트는 모델이 도구를 고르고, 고객 확인을 받아 일을 처리하며, 검증을 통과한 답만 내보냅니다.

## 구조

```
START → agent ──(도구 호출)──→ tools ──(조회 도구)──────────────→ agent        (최대 4라운드, 라운드마다 여러 도구 병렬)
          │                     └──(실행 도구)──→ confirm ⏸ 고객 확인 → agent
          └──(최종 답변)──→ verify ──(통과)──→ finalize → END
                               └──(실패, 1회)──→ agent (피드백 · 빠진 도구 확정 호출)
```

| 파일 | 역할 |
|---|---|
| `graph.py` | LangGraph `StateGraph` — 노드, 분기, 시스템 프롬프트, 턴 관리(멀티턴 이월), 스트리밍 |
| `tools.py` | 조회 도구 4개 (JSON 스키마 + 구현). 기존 서비스 함수를 감쌈. 검색 문서 속 지시문 제외 |
| `actions.py` | 실행 도구 3개 — 사전 검사(확인 문구 생성) / 실행(기존 API 라우터 함수 호출) |
| `memory.py` | 체크포인터 — `AGENT_CHECKPOINT_DB` 가 있으면 PostgresSaver, 없으면 메모리 |
| `verify.py` | 검증(번호 · 상품명 · 언어 · 의도 누락 · 거짓 실행 보고 · 형식 누출), 렌더링(`[P#]` → 상품명, 조사 보정) |
| `llm.py` | Ollama `/api/chat` tool calling (`num_ctx` 명시), 구조화 출력, 텍스트로 나온 도구 호출 복구 |
| `../../routers/agent.py` | `POST /agent/chat`, `POST /agent/resume` (SSE), JWT 로 고객 확인 |

## 도구

| 도구 | 종류 | 감싼 기능 | 비고 |
|---|---|---|---|
| `search_policy(query)` | 조회 | `rag_search.search_documents` | 유사도 0.5 미만 · 지시문이 든 청크 제외, 출처 수집 |
| `search_products(keyword, max_price, min_price, min_rating, sort, limit)` | 조회 | 상품 테이블 | 결과는 `P1, P2…` 번호로 |
| `get_user_pattern()` | 조회 | `personalized_recommendation` | 로그인 필요 |
| `get_order_status(order_number?)` | 조회 | 주문 · 주문상품 | 상태 · 운송장 · 취소 가능 여부 (로그인 필요) |
| `add_to_cart(product, quantity)` | 실행 | `routers.cart.add_to_cart` | 상품은 이번 대화의 `[P#]` 로만 |
| `cancel_order(order_number)` | 실행 | `routers.orders.cancel_order` | 결제 취소 · 재고/포인트 환원 규칙 그대로 |
| `request_human(category, title, content)` | 실행 | `routers.inquiry.create_inquiry` | 상담원 인계 (1:1 문의) |

실행 도구는 로그인한 고객에게만 보입니다. 비로그인 고객은 고를 수조차 없습니다.

## 실행은 고객 확인 후에만

1. `tools` 노드는 실행 도구를 바로 실행하지 않고 **사전 검사**만 합니다. 실행할 수 없는 요청(배송중 주문 취소, 품절, 이번 대화에 없는 상품 번호)은 이유를 돌려줘 모델이 대안을 안내합니다.
2. 실행 가능하면 **확인 문구를 서버가 DB 값으로** 만듭니다 ("'에어 플로우 러닝화 (레드)' 1개를 장바구니에 담습니다 (119,000원)"). 모델이 실행 내용을 바꿔 말할 수 없습니다.
3. `confirm` 노드가 `interrupt` 로 멈추고, 상태는 체크포인터에 저장됩니다. API 는 `confirm` 이벤트를 보내고 응답을 끝냅니다.
4. 고객이 승인하면 `/agent/resume` → 기존 API 라우터 함수로 실행합니다. 거절하면 실행하지 않고, 확인 대기 중에 새 질문이 오면 대기 중인 실행은 버립니다.

## 멀티턴

대화 상태는 `thread_id` 단위로 체크포인터에 저장합니다. 다음 턴에는 **앞 턴의 질문과 검증을 거친 최종 답변, 상품 번호 목록(catalog)과 그 요약 사실(가격 · 평점)** 만 넘기고, 도구 결과 원문은 넘기지 않습니다 (컨텍스트 예산). 요약 사실이 없으면 "두 번째 거 평점은?"에 모델이 수치를 지어냈습니다 (평가에서 발견).
그래서 "첫 번째 거 장바구니에 담아줘"의 "첫 번째 거"가 앞 답변의 `[P1]` 로 이어집니다.

## 권한 · 보안

- 고객은 `Authorization: Bearer <JWT>` 로만 확인합니다. 요청 본문으로 `user_id` 를 받지 않습니다.
- 실행 도구는 고객이 이번 질문에서 그 작업을 요청했을 때만 받습니다 (모델 판단이나 문서 속 지시로는 실행을 제안할 수 없음). 취소는 고객이 말한 상품이 그 주문에 있는지도 확인합니다.
- 대화(thread)는 시작한 고객만 이어 쓰거나 재개할 수 있습니다. 다른 고객이 같은 id 로 질문하면 새 대화로 시작하고, 재개는 403 입니다.
- 검색된 문서 속 지시문(간접 프롬프트 인젝션)은 모델에게 보여 주지 않습니다. 그래도 모델이 실행하지 않은 일을 했다고 말하면 검증에서 막습니다.

## 환각을 막는 방법

1. **상품은 번호로만:** 도구가 상품을 `P1, P2…`로 돌려주고 실제 정보는 서버 상태(`catalog`)에 둡니다. 모델은 `[P1]`만 쓰고, 이름·가격은 `finalize`가 DB 값으로 채웁니다.
2. **검증 노드:** 도구 결과에 없는 번호, 카탈로그에 없는 상품명, 한자 혼입, 추천 · 실행 요청인데 도구 미호출, 실행하지 않은 작업을 했다는 말, 상품 하나를 말하는 문장의 평점 · 가격이 DB와 다른지, 도구 호출 형식 누출, 빈 답변을 검사합니다. 실패하면 1회 재작성합니다.
3. **확정 호출:** 빠진 도구는 모델에게 다시 맡기지 않고 그래프가 호출합니다 (Ollama 에 `tool_choice` 가 없음). 모델은 인자만 구조화 출력으로 만들고, 장바구니 담기는 이번 대화의 번호 중에서만 고르게 스키마(`enum`)로 제한합니다.
4. **도구 호출 복구:** qwen2.5 가 가끔 도구 호출을 답변 텍스트로 내보냅니다. 제공한 도구 이름일 때만 호출로 복구하고, 복구하지 못한 형식은 검증에서 막습니다.
5. **LLM 서버 오류:** Ollama 5xx · 연결 끊김은 3초 뒤 한 번 재시도합니다 (GPU 오류로 엔진이 죽으면 Ollama 가 다시 띄움). 시간 초과는 지연이 두 배가 되므로 재시도하지 않고, 답변 길이는 `num_predict` 로 제한합니다.
6. **컨텍스트 예산:** 도구 결과는 상품 5개 · 규정 청크 400자, 앞 턴은 질문과 답변만, `num_ctx=8192` 명시.

## API

- `POST /agent/chat` — `{ "message": "...", "thread_id": "uuid | null" }`
- `POST /agent/resume` — `{ "thread_id": "uuid", "approve": true | false }`

SSE 이벤트: `thread` → `llm` · `tool_call` · `tool_result` → (`confirm` → 응답 끝 / 재개 시 `action`) → `verify` → `answer` → `done`
