# 포트폴리오 디자인 가이드 (참고용 키트)

다른 프로젝트에서 같은 방식의 포트폴리오(PDF + PPTX)를 만들 때 참고하는 문서입니다.
예시는 "쇼핑몰 상담 RAG 에이전트" 22쪽(표지 + 20쪽 + 마무리, v7 보고서형)이며, `preview/` 의 PNG 가 완성 모습입니다.
품질 기준은 사내 발표 자료 `abs_ax/발표자료` (예방점검 서류 검수 · 24쪽) 와 같은 수준의 도식 · 구조화입니다.

## 1. 방식 한 줄 요약

**HTML/CSS로 16:9 쪽을 그리고 → Chromium(Playwright)으로 PDF를 찍고 → 같은 쪽을 PNG로 찍어 PPTX에 넣는다.**
화면 캡처는 실제 앱을 Playwright로 조작해서 얻고, 숫자는 실제로 측정한 값만 쓴다.

```
capture.mjs (실제 앱 조작·캡처·실행 기록) → crops.py (자르기·바탕 정리) → 평가 스크립트 (지표 JSON)
        ↓                                ↓                            ↓
      pages.mjs (쪽별 문구·배치)  +  arch.mjs (SVG 도식)  +  portfolio.css (모양)
                                   ↓
                     build.mjs → PDF · PPTX (+ 넘침 검사)
```

## 2. 파일 구성

| 파일 | 역할 | 다른 프로젝트에서 |
|---|---|---|
| `build.mjs` | 쪽 조립 + 도우미 함수(`shot`, `dg`, `py`, `M`) + PDF/PPTX 출력 + 넘침 검사 | 거의 그대로 재사용 |
| `portfolio.css` | 쪽 틀, 상자, 표, 막대, 도식 부품, 캡처 프레임 등 모든 모양 | 그대로 재사용 (색 토큰만 바꾸기) |
| `arch.mjs` | SVG 도식: 선 아이콘 50여 개(`IC`), 시스템 구성(단계 삽화), 기술 구조(층 + 보안 통제 + 품질 관문), 에이전트 그래프, 보안 경로, 요약 그림 | 부품(아이콘 · 단계 상자 · 층 상자)은 재사용, 그림은 새로 |
| `fonts/` | Pretendard woff2 + 라이선스 (SIL OFL) | 그대로 |
| `pages.mjs` | 쪽별 내용 (제목·설명·도식·캡처 배치) | **새로 작성** — 예시로만 참고 |
| `capture/capture.mjs` | Playwright로 앱을 실제 조작해 캡처 (로그인, 질문 입력, LLM 응답 대기) | 시나리오만 바꿔 재사용 |
| `capture/crops.py` | 캡처를 내용만 남게 자르고, 회색 바탕을 흰색으로, 타일 비율 맞춤 | 좌표만 바꿔 재사용 |
| `package.json` | `playwright`, `pptxgenjs` | 그대로 |
| `preview/*.png` | 완성 쪽 미리보기 (디자인 참고 이미지) | 참고용 |

## 3. 디자인 규칙 (v6 보고서형 — 사용자 피드백 + 참고 자료 기준)

- **색: 남색 제목 + 강조 1색 + 회색 단계.** `--navy #1b3058` · `--ac #2b5fb4` · `--g50…g700`. **그라데이션 금지.**
- **역할 색 3개는 도식에서만, 뜻이 고정:** LLM `--llm #b45f1e` · 코드/시스템 `--sys` · 고객 `--cust #4d7d38`. 쪽마다 같은 뜻으로 쓰고 범례를 붙인다. 장식용 색은 쓰지 않는다.
- **각진 상자.** 둥근 카드 · 알약 표시 · 그림자 없음. 상자는 위쪽 굵은 남색 선(`.panel`, `.dec`, `.eset`), 표 머리는 색 띠 없이 남색 밑줄(`table.grid`).
- **그림자 · 반투명 금지.** `box-shadow`, `opacity`, `rgba` 는 PDF에서 SMask가 되어 일부 뷰어에서 회색 사각형으로 보인다. 단색과 `color-mix` 로 만든 옅은 색만.
- **서체는 Pretendard**, 숫자는 고정폭(`tabular-nums`). `--mono: Consolas, "Pretendard"` 로 한글만 Pretendard.
- **제목은 "주제: 한 줄"** ("시스템 구성: 질문부터 답변까지, LLM · 코드 · 고객이 맡는 곳"), 아래 **핵심 줄 하나**(`msg`, 왼쪽 강조 막대, 숫자는 강조색 굵게). 슬라이드 문구는 **개조식**("~함", 명사로 끝냄).
- **한 쪽에 그림 하나가 중심:** 단계 삽화 도식 · 층 구조 · 관문 · 점 매트릭스 · 같은 축척 막대 · 실제 화면. 글로 풀 내용은 발표자 노트로.
- **넘치면 글자를 줄이지 않고** 행 여백 · 핵심 줄 길이 · 쪽 나누기로 맞춘다 (빌드가 넘침 0 이어야 함). 카드가 6장 넘게 한 쪽에 들어가면 두 쪽으로 나눈다.
- **리듬:** 본문은 세로 가운데(`.body{justify-content:center}`), 각주는 내용 바로 아래. 핵심 줄 21px, 본문 · 표 13~14px, 각주 12.8px 아래로 내리지 않는다.
- **자기 설명형 군더더기 금지:** "혼자 만들었습니다", 코드 줄 수, 이 문서를 어떻게 만들었는지 같은 메타 설명.
- **숫자는 측정값만.** 스크립트 결과(JSON)를 빌드가 읽어 넣는다. 반복 측정으로 우연을 배제하고, 측정 조건이 다른 값은 나란히 비교하지 않는다.
- **캡처는 내용만.** 번호 표시는 캡처 때 기록한 요소 위치로 자동 배치한다.


## 5. 핵심 부품 (`build.mjs` 도우미 + `arch.mjs` 도식 + `portfolio.css` 클래스)

### 5-0. SVG 도식 (`arch.mjs`) — 참고 자료 방식
- **단계 상자 + 작은 그림:** 단계마다 머리(번호 + 맡는 주체, 역할 색) · 그 단계가 하는 일을 그린 작은 삽화(150 × 100) · 제목 · 한 줄. 사이에 둥근 꺾쇠, 건너뛰기 · 되돌아가기는 위쪽 경로(점선 = 되돌림).
- **경계 상자:** 실행 환경(서버 · 로컬 PC)을 남색 테두리로 감싸고, 바깥(고객 · 외부 API 없음)은 위에 아이콘으로. 아래에 "기반" 줄(모델 · DB · 상태).
- **층 구조:** 왼쪽 층 이름(화면 · 서버 · 모델 · 저장) + 층마다 상자(아이콘 · 기술 알약 · 작은 카드) + 오른쪽 보안 통제 패널 + 아래 품질 관문 띠.
- 글자는 `foreignObject`(HTML)로 넣는다 → 줄바꿈 · 서체가 본문과 같고 PDF에서도 글자로 남는다.
- 화살표 머리는 역할마다 `marker` 하나씩 (도식마다 id 앞글자를 다르게).

### 5-1. 흐름도 `dg()` — 좌표로 노드를 놓고 화살표는 자동
```js
dg({
  w: 1160, h: 420,
  nodes: {
    a: { x: 0,   y: 30, w: 160, h: 76, t: 'PDF 업로드', s: 'CRM · 50MB 검증' },
    b: { x: 200, y: 30, w: 160, h: 76, t: '임베딩', s: 'bge-m3 · 1024d', k: 'a' },   // k:'a' 강조 테두리
    c: { x: 400, y: 30, w: 150, h: 290, t: '벡터 DB', k: 'd c' },                    // 'd' 어두운 노드, 'c' 가운데 정렬
    g: { x: 0, y: 0, w: 400, h: 22, t: '① 색인', k: 'lbl' },                         // 'lbl' 글자 라벨, 'g' 점선 그룹 상자
  },
  edges: [['a', 'b'], ['b', 'c', '청크 8 · 1024d', { hot: true }]],                   // 라벨 · 강조선 · {a:'b', b:'t'} 출발/도착 면
})
```
노드 종류: 기본(흰 카드) · `a` 강조 테두리 · `f` 강조색 채움 · `d` 어두운 칸 · `g` 점선 그룹 · `lbl` 라벨 · `c` 가운데.

### 5-2. 화면 캡처 프레임 `shot()`
```js
shot('clean/rag-chat', { url: 'AI 규정문서', full: true })          // 정리된 이미지 전체
shot('hero', { crop: [940, 112, 472, 240], markers: [[91, 30, 1]] }) // CSS 좌표로 자르기 + 번호 표시
```
브라우저 창처럼 위에 회색 막대(●●● + 주소)를 붙인다. `bar: false` 로 막대 없이.

### 5-3. 숫자 · 그래프
- `.strip` — 가로 숫자 띠 (`<div><b>5 / 5</b><span>설명</span></div>` 반복)
- `.hbar` — 가로 막대그래프 (라벨 · 막대 · 값 3칸 그리드, `.fl.hot` 강조)
- `.big` — 큰 숫자 카드, `.cells` — 채점 결과 칸(✓/✕), `.tline` — 처리 시간 타임라인
- `.simbar` — 유사도 막대, `.evi` — 검색 근거 카드, `.hx` — 실제 답변 원문 발췌(환각 표시)

### 5-4. 갤러리 타일
`crops.py` 로 모든 타일을 같은 비율(1.75)로 흰 여백 패딩 → `.tiles` 3열 그리드. 설명이 붙는 기능 타일은 `.ftile` (캡처 + 제목 + 불릿 3개).

### 5-5. 에이전트 사례 부품 (v6)
- `.sum2` / `.sum3` — 한 장 요약: 전후 그림 두 장 + 비교 막대 · 평가 막대 · 결론
- `.bars` — 각진 막대 (`[이름, %, 값, true=우리]`, 우리 = 강조색 · 비교 = 회색 · `'k'` = 진한 회색), 이름은 "항목 · 기존 / 항목 · 에이전트"
- `.strip` — 역할 색 단계 띠 (아이콘 + 번호 + 한 줄), `.nl` — 캡처 번호 설명
- `.lanes` — 질문 유형별 흐름 줄: 질문 말풍선 → LLM이 하는 일(실제 호출 형태) → 코드가 정하는 것(`.rc` 코드 표시) → 고객에게 가는 때
- `.gates8` / `.gate` — 검사 관문 (번호 · 아이콘 · 무엇 · 실제 사례 · 처리 · 발견 경로)
- `table.mx` — 개선 과정 점 매트릭스: 행 = 찾은 실패, 열 = 장치(아이콘), `+` = 이 실패로 고친 장치, 회색 점 = 이미 있던 장치
- `.lane2` — 두 갈래 단계 줄 (RAG 색인 · 검색), `.evi` — 검색 근거 카드
- `.dec` — 설계 결정 카드 (선택 / 대안 / 근거 / 대가 + `.dec-viz` 근거 차트), `.waf` — 칸 차트 (답변 하나 = 칸 하나)
- `.wf` — 실행 기록 폭포 그래프 (LLM = 주황, 도구 = 파랑), `.kpis` — 숫자 띠
- 캡처 위 번호 표시는 좌표를 손으로 넣지 않는다. 캡처 스크립트가 요소 위치를 `shots/<이름>.boxes.json` 에 기록하고 빌드가 계산한다

## 6. 품질 확인 (빌드마다)

1. `node build.mjs --preview` → `preview/*.png` 로 쪽별 확인
2. 빌드가 **넘침 검사** 경고를 출력 (바닥글 침범, 카드 내용 넘침, 코드 잘림)
3. 완성 PDF를 PDFium으로 다시 그려 확인 (`pypdfium2`) — 크롬·엣지 PDF 뷰어와 같은 엔진
4. PDF 안 `/SMask` 개수가 0인지 확인 (회색 사각형 방지)

## 7. 쪽 구성 (RAG 에이전트 직무, 22쪽 — 보고서형)

에이전트 포트폴리오는 기능 나열이 아니라 **요약 → 문제 → 설계 → 평가 → 개선** 순서로 보여 준다.
면접관이 궁금한 것은 "무엇을 만들었나" 보다 "LLM이 틀릴 때 어떻게 알고, 어떻게 막았고, 무엇을 실행하게 했고, 왜 그렇게 골랐나" 이다.
"에이전트"라고 부르려면 조회만이 아니라 **확인 후 실행 · 멀티턴 · 연쇄 도구 사용 · 권한 · 인젝션 방어**를 실제로 보여 줘야 한다.

| 장 | 쪽 | 중심 요소 |
|---|---|---|
| — | 표지: 제목 · 장 목록 · 한 줄 + 실제 화면 | 캡처 |
| I. 요약 | 한 장 요약 · 실제 동작(실행 기록) · 확인 후 실행 | `.sum2` · `.bars` · `.wf` · `.strip` + 캡처 2장 |
| II. 문제 | 기존 챗봇의 한계 | `.pcols` |
| III. 설계 | 시스템 구성 · 기술 구조 · 에이전트 그래프 · 질문 유형별 역할 · 도구 · 컨텍스트 예산 · RAG · 답변 검증 · 보안 · 설계 결정 | `A.archSvg` · `A.techSvg` · `A.graphSvg` · `.lanes` · `table.grid` · `.bud` · `.lane2` · `.gates8` · `A.secSvg` · 설계 결정 2쪽 (`.decs.d3`, 쪽마다 3장) |
| IV. 평가 | 평가 설계 · 채점 결과 · 기존 대비 결과 · 개선 과정 | `.esets.e6` · `.smx.one` · `.cmp` · `.bars` · `table.mx` |
| V. 확장 | 그 밖의 AI 기능 | 캡처 · `.chain` |
| — | 마무리: 다음 단계 3개 + 연락처 | |
