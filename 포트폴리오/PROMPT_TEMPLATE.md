# 다른 프로젝트 Claude에게 줄 요청문 (복사해서 사용)

`design-kit.zip` 을 새 프로젝트 폴더에 풀어 두고, 아래 [대괄호]만 채워서 보내세요.

---

이 프로젝트로 [지원 직무: 예) RAG·LLM 에이전트 개발자] 지원용 포트폴리오를 PDF와 PPTX로 만들어 줘.
디자인과 만드는 방식은 `design-kit/` 을 그대로 따라 줘. `DESIGN_GUIDE.md` 를 먼저 읽고, `preview/*.png` 가 목표 모습이야.

**나에 대한 정보 (이것만 사실로 써 줘)**
- 이름: [이름] / 경력: [n년차] / 지원 직무: [직무]
- 프로젝트 성격: [1인 개인 프로젝트 / n명 팀에서 ○○ 담당]
- 꼭 강조하고 싶은 것: [예) RAG 파이프라인, 평가로 품질 개선한 경험]
- 넣지 말 것: [예) 회사명, 특정 기능]

**진행 순서**
1. 코드를 먼저 끝까지 분석해서, 직무와 관련된 기능을 "실제로 동작하는 것 / 일부만 된 것 / 문서에만 있는 것"으로 나눠 알려 줘. 과장 없이.
2. 앱을 로컬에서 실제로 실행해 줘. DB나 외부 서비스가 없으면 로컬 대체 환경을 만들어도 돼. ([DB 비밀번호·실행 방법·테스트 계정 등])
3. 쪽 구성안(12~20쪽, 쪽마다 핵심 줄 하나)을 먼저 보여 주고, 그다음에 만들어 줘. 에이전트 프로젝트면 `DESIGN_GUIDE.md` 7장 순서(요약 → 문제 → 설계 → 평가 → 확장)로.
4. 초안 PDF를 빨리 만들어서 중간중간 계속 공유해 줘.

**내용 규칙**
- 화면은 실제 앱을 Playwright로 조작해서 캡처해 줘. 내용 영역만 자르고, 회색 바탕이나 잘린 말풍선이 남지 않게 해 줘.
- 숫자는 직접 측정한 값만 써 줘. 평가셋을 만들어 자동 채점하고, LLM 결과는 여러 번 반복해서 재 줘. 측정이 틀렸으면 고쳐서 다시 재 줘.
- 쪽마다 흐름도 · 실측 그래프 · 실제 화면 중 하나가 중심이고, 글은 제목과 한 줄 설명만.
- "평가로 찾은 문제 → 원인 → 해결 → 재측정"을 꼭 넣어 줘. 에이전트라면 실제 실행 기록(도구 호출 순서 · 시간)과 검증에 걸린 실제 예도. 합격에 유리한 것만 남기고, 꼭 필요하지 않은 기술 나열이나 긴 코드는 빼 줘.
- 자기 설명형 문구는 쓰지 마: "혼자 만들었습니다", "회사 다니며 만든 프로젝트", "직접 만들어", "~한 기록입니다", 코드 줄 수, 이 문서를 어떻게 만들었는지 같은 메타 설명.

**디자인 규칙**
- 보고서형: 남색 제목 + 강조색 하나 + 회색 단계, 서체는 Pretendard. 그라데이션 · 그림자 · 반투명 · 둥근 카드는 쓰지 마 (PDF에서 회색 사각형이 생김).
- 도식에는 역할 색 3개만 (LLM · 코드/시스템 · 사람/고객), 쪽마다 같은 뜻 + 범례.
- 아키텍처는 `arch.mjs` 방식으로: 단계 상자마다 작은 그림 + 맡는 주체, 실행 환경 경계 상자, 아래 기반 줄(모델 · DB · 상태). 기술 구조는 층(화면 · 서버 · 모델 · 저장) + 보안 통제 패널 + 품질 관문 띠.
- 표보다 시각화 먼저: 관문 도식, 점 매트릭스, 같은 축척 막대, 칸 차트, 흐름 줄(LLM → 코드 → 사람).
- "설계 결정과 트레이드오프" 쪽을 넣어 줘: 결정마다 선택 · 대안 · 근거(측정값) · 감수한 비용.
- 16:9, 한 쪽에 그림 하나가 중심. 제목은 "주제: 한 줄", 그 아래 핵심 줄 하나(숫자는 강조색). 문구는 개조식(~함, 명사로 끝냄).

**결과물**
- 한 폴더에 PDF · PPTX(발표자 노트 포함)와 만드는 코드 전부. 문구만 고쳐도 다시 빌드되게 해 줘.
- 빌드마다 넘침 검사를 하고, 완성 PDF는 PDFium으로 다시 그려서 쪽마다 직접 확인해 줘.

## 잘 되게 하는 요령

- **사실 정보를 처음에 확실히 주기:** 이름·경력·1인/팀 여부·담당 범위. 이게 없으면 Claude가 git 기록을 보고 추측합니다
- **실행 정보 주기:** DB 비밀번호, `.env` 위치, 테스트 계정. 실제 화면 캡처와 측정이 여기서 결정됩니다.
- **쪽 구성안을 먼저 승인하기:** 다 만든 뒤 고치는 것보다 훨씬 빠릅니다.
- **피드백은 구체적으로:** "알록달록하다", "이 회색 여백", "이 문구 필요 없다"처럼 화면을 캡처해서 짚어 주면 같은 유형을 전체에서 찾아 고칩니다.
